# Code of conduct

## The standard this project adopts

This project adopts the **Contributor Covenant, version 2.1**, as its code of
conduct.

The Covenant is published at <https://www.contributor-covenant.org/version/2/1/code_of_conduct/>
and is licensed CC BY 4.0, which is a permissive licence for a document and is
compatible with this repository's dependency rules.

The full Covenant text is deliberately **not vendored into this repository**.
This project writes its own material rather than copying other projects' text,
and a copied code of conduct drifts from the version it claims to be. The link
above is the authoritative wording; everything below is this project's own
statement of scope and process, which the Covenant expects a project to supply
for itself.

In short, the standard is: participate in a way that makes it possible for
someone unlike you to participate too. Harassment, personal attacks,
demeaning or discriminatory comments, publishing someone's private information,
and sustained disruption are not acceptable here, whatever the technical merit
of the person doing them.

## Scope

This code of conduct applies:

- in every space this project controls, which today means the repository's
  issues, pull requests, discussions, code review comments, and commit
  messages;
- to every contribution and every artifact of participation, including code,
  documentation, and reports; and
- when someone is representing the project in a public space, for example by
  posting under its name or as an appointed representative.

It applies to everyone equally: reporters, contributors, reviewers, and
maintainers. Being the maintainer is not an exemption.

It does **not** extend to a person's unrelated conduct elsewhere. This project
does not police behaviour outside spaces it controls, except where that
behaviour is directed at a member of this community because of their
participation here, in which case it is in scope.

## Applying the technical standards is not a conduct problem

The project's engineering rules are strict on purpose: honest labelling, no
forced green, evidence for every claim, permissive dependencies only, and no
number that has not been read out of an artifact. Enforcing those rules in a
review, including asking for a claim to be withdrawn or a status to be
demoted, is not unkindness and is not covered by this document.

The line is between the work and the person. "This claim is not supported by the
evidence, here is why" is the review this project wants. Anything that is about
the contributor rather than the contribution is not.

## Reporting a concern

Report privately, through the repository on the forge where you obtained this
copy. Two routes, in order of preference:

1. **A private message to the repository owner on the forge.** This is the
   default channel. A code of conduct report is not a bug and should not be
   filed as one.
2. **A minimal public issue asking to be contacted privately**, if no private
   route is available to you. Do not put the details in it. Say only that you
   have a conduct concern and would like a private channel.

Deliberately, no email address is published here. Publishing an address that
nobody has verified would be worse than publishing none: it would look like a
channel and silently drop reports.

If your concern is about the person who receives reports, say so in the report.
The project is small enough that the honest answer is that there may be nobody
else to escalate to, and that limitation is stated here rather than hidden.

### What a useful report contains

- What happened, and where (a link is ideal).
- When it happened.
- Who was involved, and whether anyone else saw it.
- Whether it is ongoing.
- What you would like to happen, if you have a view. It is fine not to.

You do not have to be the target to report something.

## What happens next

- **Acknowledgement.** You will get a reply confirming the report was received.
- **Review.** The report is read in full, along with whatever record exists in
  the repository.
- **Response.** Depending on what is found, the response ranges from a private
  correction, through a request for a public apology or the removal of a
  comment, to a temporary or permanent block from the project's spaces.
- **Outcome.** You will be told that the report was handled. You may not be
  told the details of what was done to another person, because that is their
  private matter.

No fixed response time is promised here. This is a small project, and a
timeline nobody can commit to is not a commitment, it is an unkept promise
waiting to happen. What is promised is that a report will be read and answered
rather than ignored.

Reports are kept confidential. A reporter's identity is not shared with the
person reported without the reporter's agreement.

## Retaliation

Retaliating against someone for making a good-faith report is itself a
violation, and is treated as a serious one.

A report made in bad faith, to harass someone or to win a technical argument, is
also a violation. Being mistaken is not bad faith: reporting something that
turns out to be a misunderstanding carries no penalty at all.
